# GymBrat schema change

- Source files: `db/schema.ts` (Drizzle types), `db/ensure-schema.ts` (the schema actually ensured at runtime - keep in sync, idempotent `IF NOT EXISTS`/guarded `ALTER`), `db/migrations/NNNN_name.sql` (+ `meta/`, generated by `npm run db:generate`; next number follows the last file).
- Steps: edit `schema.ts` -> `npm run db:generate` -> review the SQL -> mirror in `ensure-schema.ts` -> test with `db/test-memory-db.ts`.
- Additive only by default: new nullable/defaulted columns; never drop/rename in the same release as the code that stops using it. Destructive change = ask the user.
- Indexes for every new `WHERE`/`ORDER BY` on user data, leading with `user_id` (see `db/workouts-indexes.test.ts` for the test pattern).
- Backfills: batched, resumable, no long locks (Turso).
- Never run `db:push`, `db:reset` or migrations against production; never print connection strings/tokens.
- Binary data (photos) does not belong in rows as data URLs (known debt) - do not add more.
